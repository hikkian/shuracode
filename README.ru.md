ShuraCode — агент для программирования из проекта [Shura](https://github.com/hikkian/shura), который
запускает Tiel-Coder 35B на вашей собственной видеокарте. Всё работает на вашем компьютере: модель, агент и
его память.

- **Постоянная память.** Скажите «запомни, что я предпочитаю pytest», и каждая следующая сессия будет это
  знать. Память — обычные markdown-файлы, их можно читать, править и удалять.
- **Два режима.** **Build** вносит изменения. **Plan** только читает и предлагает, и даже перенаправление
  вывода в терминале не позволит ему что-то записать. Переключение — клавишей Tab.
- **Команды.** `/remember`, `/forget`, `/memory`, `/test`, `/commit`, `/review` и `/guide`: полный список команд и клавиш на английском или русском (также в [docs/COMMANDS.md](docs/COMMANDS.md)).
- **Статус модели.** Внизу экрана видно, загружена ли локальная модель, загружается или спит.
- **Офлайн по умолчанию.** Никаких проверок обновлений, публикации сессий, загрузки каталогов моделей и
  телеметрии.

## На основе OpenCode

ShuraCode построен на [OpenCode](https://github.com/anomalyco/opencode) (MIT), который служит ему движком.
Это не форк OpenCode: ShuraCode добавляет свой слой через публичные точки расширения OpenCode.

| Слой | Что добавляет |
|---|---|
| `bin/shuracode` | команду, свою папку настроек, офлайн-настройки и имя процесса `shuracode` |
| `plugin/shuracode.tsx` | плагин интерфейса: логотип, нижняя строка, боковая панель, подсказки, заголовок окна, статус модели |
| `plugin/server.ts` | серверный плагин: агент представляется как ShuraCode |
| `mcp/memory.py` | сервер памяти (только стандартная библиотека Python) |
| `config/`, `commands/`, `themes/` | подключение модели, права доступа, правила, команды, тема |

Внутри движка ничего не меняется, поэтому обновления движка сохраняют внешний вид, название и возможности
ShuraCode. `shuracode update` ставит новый движок рядом с текущим и запускает на нём самопроверку:

- логотип, нижняя строка и заголовок окна на месте;
- агент по-прежнему представляется как ShuraCode и называет модель, на которой работает.

На новый движок ShuraCode переключается, только если прошли все проверки. Если хоть одна не прошла, вы
остаётесь на текущей версии. `shuracode rollback` возвращает предыдущую.

## Установка

Вместе с Shura: `setup.sh` сам ставит ShuraCode. Отдельно:

```bash
git clone https://github.com/hikkian/shuracode.git && cd shuracode
./install.sh                      # движок, настройки, память, команда `shuracode`
shuracode doctor                  # проверить, что всё в порядке
```

Требования: Linux x86_64, Node.js 18+, Python 3.10+ и модель, доступная через OpenAI-совместимый API. По
умолчанию это gateway Shura по адресу `http://127.0.0.1:8080/v1`. Другой адрес:
`./install.sh --base-url URL --status-url ""`.

## Использование

```bash
cd your-project && shuracode      # открыть интерфейс
shuracode run "объясни src/app.py"   # один запрос без интерфейса
shuracode update | rollback | doctor | version | help
```

| Команда | Что делает |
|---|---|
| `/remember [факт]` | сохраняет факт; без аргумента сохраняет самое полезное, что выяснилось в этой сессии |
| `/forget <тема>` | находит подходящую заметку и удаляет её; если подходят несколько, спрашивает |
| `/memory` | показывает, что сохранено, и отмечает устаревшие заметки и дубли |
| `/test` | выясняет, как в проекте запускаются тесты, запускает их, чинит падения и показывает настоящий результат |
| `/commit` | делает коммит одного логического изменения в стиле репозитория; никогда не пушит и не добавляет подписей |
| `/review` | проверяет незакоммиченные изменения (или коммит, ветку, PR) |

## Память

Каждая заметка — отдельный markdown-файл в `~/.local/share/shuracode/memory/`. У каждой есть тип:

- `user`: кто вы и как работаете;
- `feedback`: исправления и подтверждённые подходы;
- `project`: знания о проекте, которых нет в коде;
- `reference`: ссылки.

Оглавление `MEMORY.md` загружается в каждую сессию, поэтому модель знает, что помнит, ещё до первого шага.
Короткие заметки видны в оглавлении целиком.

Модель работает с памятью через четыре инструмента (`memory_save`, `memory_read`, `memory_search`,
`memory_delete`). Сервер памяти следит за правилами:

- один факт — один файл;
- сохранение под существующим именем обновляет заметку;
- оглавление пересобирается после каждого изменения;
- лимиты: 100 заметок, до 2000 символов в каждой;
- всё, что похоже на пароль или токен, отклоняется.

Когда что-то запоминать, решают правила в [`config/AGENTS.md`](config/AGENTS.md). Отдельной модели-
«библиотекаря» нет, поэтому память не тратит лишних обращений к модели. На диск пишется только при
сохранении или удалении заметки.

Проверено на Tiel-Coder: правило, сохранённое в одной сессии, применили три новые сессии из трёх. Когда
пользователь передумал, существующая заметка обновилась, а дубль не появился. GitHub-токен сохранить
отказались.

## Build и Plan

| Режим | Файлы | Терминал |
|---|---|---|
| Build | правка разрешена | тесты, git (кроме push) и команды только для чтения выполняются без вопросов; остальное — с подтверждением; `rm -rf`, `mkfs`, `reboot` и подобные запрещены |
| Plan | правка запрещена | без вопросов выполняются только команды для чтения (`git status/diff/log/show`, `ls`, `cat`, `grep`, `rg`, `find` и т.п.); всё с `>` или `tee` — с подтверждением; `find -delete` запрещён |

Каждое правило проверено так: тестовая модель просила выполнить команду, и мы смотрели, что произошло на
самом деле.

## Где что лежит

| Путь | Что |
|---|---|
| `~/.config/shuracode/` | `shuracode.json`, `tui.json`, `AGENTS.md`, `commands/` |
| `~/.local/share/shuracode/engine/` | текущий и предыдущий движок |
| `~/.local/share/shuracode/memory/` | память (папка `0700`, файлы `0600`) |
| `~/.local/bin/shuracode` | команда |

Историю сессий и кэши движок хранит в своих стандартных папках (`~/.local/share/opencode`,
`~/.cache/opencode`), а копию темы — в `~/.config/opencode/themes`.

## Ограничения

- Справка `--help` у подкоманд движка и несколько редких диалогов по-прежнему показывают название движка.
  Чтобы это поменять, нужен форк.
- Проверено на Fedora 44 с Ghostty и GNOME. Другие дистрибутивы Linux и терминалы должны работать, но не
  проверялись.
